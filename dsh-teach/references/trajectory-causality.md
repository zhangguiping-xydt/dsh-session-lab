# 轨迹因果切片方法

会话按时间记录“发生了什么”，不直接证明“什么导致了成功”。提炼 Skill 时使用以下四类标签，不把共现误写成因果。

## 四类动作

### 必要动作

满足至少一项：

- 直接产生最终 diff、配置、文件或外部状态；
- 直接发现随后被修复的根因，并且后续修改引用了该证据；
- 执行了预先声明的验收，结果决定继续、回滚或完成；
- 用户纠正后替代了先前错误动作，最终结果依赖替代方案。

### 辅助动作

缩小搜索范围、解释背景或提高置信度，但删除后仍能由其他已记录证据完成目标。辅助动作可以写成“按需使用”，不应成为所有执行的固定成本。

### 失败弯路

工具失败、假设被证伪、改动被撤销、重复搜索或用户明确否定的路径。Skill 应提取其“避免条件”或“失败后的分支”，而不是复刻该动作。

### 偶然动作

与目标同时出现，但既未影响产物也未影响判定，例如无关文件浏览、环境噪声、重复解释。默认删除。

## 证据强度

从强到弱排列：

1. 可重复的测试或机器判分器；
2. 最终 diff 与目标行为之间的直接对应；
3. 工具返回的结构化状态；
4. 用户对具体结果的确认；
5. Agent 的自然语言总结；
6. 仅凭步骤先后顺序作出的推测。

等级 5、6 不能单独支持强制规则。把它们写入评测假设，再用新任务验证。

## 处理用户纠正

用户纠正是高价值信号，但仍需区分：

- 目标纠正：改变了真正要完成的结果，应进入触发和验收；
- 范围纠正：限定允许修改或禁止动作，应进入安全边界；
- 表达偏好：只影响输出风格，不应改变核心工作流；
- 一次性事实：只属于原项目，应参数化或移入项目参考资料。

## 参数化检查

逐项搜索并处理：用户名、主目录、仓库名、分支名、Session ID、工号、主机名、内网域名、API 地址、端口、模型名、日期、绝对路径和一次性阈值。每一项只能落入以下三类之一：

- 新任务输入；
- 明确且有依据的默认值；
- 不属于通用 Skill，删除。
