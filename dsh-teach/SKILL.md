# 从成功会话炼成可验证 Skill

最终交付的不是聊天摘要，而是一份能在新会话中触发、执行、校验并安全失败的 Skill。只有当独立任务证明它有用后，才称其为“已学会”。

## 不可妥协的原则

- 以会话事件、工具调用、工作区改动和验收结果为证据；不要把模型的自我解释当作事实。
- 区分必要动作、辅助动作、失败弯路和碰巧出现的动作；不要照抄整条轨迹。
- Skill 必须描述输入、前置条件、输出、失败方式和验收标准，不能只写提示词技巧。
- 默认把路径、账号、Session ID、内部地址、密钥、Token 和项目专有名词视为不可发布信息。
- 原任务重跑只能证明可复现，不能证明可泛化。推广前必须使用未参与编写的变体任务。
- 在用户审阅生成物与评测报告前，不要复制到用户级 Skill 根目录，也不要覆盖同名 Skill。

## 所需输入

优先使用 DSH Web 中 `/export` 下载的 ZIP；单个 `session.jsonl` 也可以。若当前组合已挂载 `session_search`、`session_event_read` 等只读工具，可以先用它们定位候选会话，但最终证据仍应保存成稳定文件。

`$DSH_HOME/sessions/**/session.jsonl.zstd` 是内部持久化文件，不是 `/export` 的逻辑 JSONL；即使手工解压，也可能含 `text-chunks` 等打包存储记录。必须通过 Web `/export`，或用官方 SDK/持久化读取器还原逻辑 Session Event 后再分析。

同时尽量取得以下材料：

- 成功标准，例如测试命令、目标文件、可观察行为或人工确认；
- 会话结束时的代码 diff 与测试结果；
- 允许泛化的范围和必须拒绝的边界；
- 至少五个未参与 Skill 编写的变体任务，其中至少两个是“不应触发或应安全拒绝”的边界任务。

缺少成功标准时，可以产出“候选 Skill”，但不得标记为已验证。

## 完整工作流

### 1. 固化原始证据

保留原始导出文件只读，不在原文件上脱敏或改写。记录文件 SHA-256、采集时间、DSH/SDK Runtime 版本、模型选择、Agent Preset、工作区基线提交和未提交 diff。原始事件证据默认属于私密材料，不能因为报告里有哈希就直接公开。

使用本 Skill 的分析脚本生成只含脱敏预览的轨迹清单：

```bash
python3 <本 Skill 目录>/scripts/teach.py analyze <导出 ZIP 或 session.jsonl> --output-dir <工作目录>/teach-evidence
```

输出目录必须尚不存在，脚本拒绝覆盖已有分析。脚本产出 `trajectory.json` 与 `trajectory.md`；它只做确定性整理，不会判断哪些步骤具有因果作用。

### 2. 做因果切片

逐个目标建立证据表，列出：

| 字段 | 必须回答的问题 |
|---|---|
| 目标 | 用户真正要改变的可观察结果是什么？ |
| 前置条件 | 没有它就不能执行的环境、权限、文件或工具是什么？ |
| 成功证据 | 哪条测试、diff、工具结果或用户确认证明目标达成？ |
| 必要动作 | 删除后会使成功证据消失的动作是什么？ |
| 辅助动作 | 提高定位速度但不改变最终结果的动作是什么？ |
| 失败弯路 | 哪些动作失败、被撤销或被用户纠正？如何避免重演？ |
| 可变参数 | 哪些路径、模块、命令、阈值和输出位置必须由新任务提供？ |
| 安全边界 | 哪些输入必须请求确认、只读处理或明确拒绝？ |

无法用事件、文件或测试支撑的推断，标记为“待验证假设”，不要写成强制步骤。详细判定方法见 `references/trajectory-causality.md`。

### 3. 抽象任务约定

先写一个与实现无关的任务约定，再写 `SKILL.md`：

- 触发：用户会怎样表达需求，哪些相似请求不应触发；
- 输入：必需输入与可选输入，缺失时如何获取或澄清；
- 输出：文件、报告、代码改动或外部状态；
- 不变量：任何情况下都不能破坏的行为；
- 验收：机器可检查项优先，人工判断项必须给出判据；
- 失败：权限不足、材料缺失、工具不可用和结果不确定时如何停止。

把原会话中的绝对路径改为角色名称，例如“仓库根目录”“导出文件”“目标模块”；把项目名改为能力描述；把一次性的命令输出改为检查规则。不得通过删除约束来获得“通用性”。

### 4. 构建 Skill Bundle

生成一个单层目录 `<skill-name>/SKILL.md`。名称使用 kebab-case。正文只保留 Agent 每次执行都需要的决策与流程；把长格式、协议和领域资料放入 `references/`，把可重复且确定的处理放入 `scripts/`，把模板放入 `assets/`。

Frontmatter 的 `description` 同时承担路由职责，必须写明“做什么、何时使用、何时不用”。不要在正文中依赖未明确引用的资源。

每个生成 Skill 至少包含：

- 可观察的完成定义；
- 输入缺失、工具失败与危险操作的处理；
- 一条正常路径和关键边界路径；
- 对应实际产物的验证命令或验证方法；
- 来源与评测记录的位置，但不嵌入原始私密会话。

### 5. 脱敏并做静态校验

先人工复核生成目录，再执行：

```bash
python3 <本 Skill 目录>/scripts/teach.py validate <候选 Skill 目录>
```

校验器检查名称、frontmatter、显式资源引用、嵌套 Skill、常见密钥形态和用户绝对路径。校验通过不代表“没有秘密”；工具输出、业务数据和图片仍需人工检查。

### 6. 设计独立评测

在阅读候选 Skill 正文前冻结评测任务与判分器。不要让编写 Skill 的同一次轨迹同时负责发明全部测试答案。

评测至少覆盖：

1. 近邻变体：目标相同，但路径、命名、数据或项目结构不同；
2. 结构变体：需要相同原理，但步骤顺序或可用工具不同；
3. 边界任务：描述相似但不应触发，或缺少前置条件应安全停止；
4. 干扰任务：包含原会话中出现过但与成功无因果关系的信息。

对每个任务成对运行 baseline（不加载候选 Skill）和 treatment（加载候选 Skill）。保持模型、推理强度、工具、权限、工作区基线和任务文本一致；每次使用全新会话与可丢弃工作区，随机化先后顺序。具体记录格式见 `references/evaluation-protocol.md`。

每次运行必须保存经过确定性敏感字段替换的完整逻辑 Session Event 为 `dsh-teach-run-evidence/v1` JSON，并在 `results.jsonl` 中记录文件 SHA-256。保留原始事件的私密副本供审计，发布仓库只放人工复核后的脱敏证据。评测报告必须从事件重新计算实际 provider/model/reasoning effort、最终可见回复、Skill 加载、工具安全、Token 和耗时，不能信任运行器自行填写的布尔摘要。

### 7. 判定是否推广

推广条件必须在运行前写进 `eval/manifest.json`。至少满足：

- 所有安全与边界任务通过；
- baseline 从未加载候选 Skill；
- treatment 没有新增越权写入、泄密或跳过验收；
- 主要成功指标优于 baseline，或在成功率不下降时显著减少工具步骤、Token 或耗时；
- 失败样本已分类，报告中保留反例，不只展示成功案例；
- 原任务本身不计入泛化成功率。

少于五个变体只能称为冒烟验证；对外宣称稳定提升时，增加任务量和重复次数，并报告样本数与不确定性。

所有结果落盘后必须运行评测判定器。它会拒绝不成对、证据哈希不匹配、证据与结果不一致、实际请求配置偏离清单的数据，并生成报告：

```bash
python3 <本 Skill 目录>/scripts/teach.py eval-report <候选 Skill>/eval --require-promotion
```

只有 `report.json` 的 `promoted` 为 `true` 且人工复核任务与证据无误，才能进入安装或发布步骤。

### 8. 安装与发布

通过评测后，生成以下最终产物：

```text
<skill-name>/
├── SKILL.md
├── scripts/                 # 可选，确定性操作
├── references/              # 可选，按需读取
├── assets/                  # 可选，模板或静态资源
└── eval/
    ├── manifest.json
    ├── tasks.jsonl
    ├── results.jsonl
    ├── evidence/                # 每次运行的哈希绑定脱敏完整事件；公开前仍需人工复核
    └── report.md
```

DSH 默认发现项目根下 `.dsh/skills/<skill-name>/SKILL.md`、`.agents/skills/<skill-name>/SKILL.md`，以及用户根下对应目录。当前这份开发目录不会仅因存在而自动安装；经用户确认后再复制到所需根目录，或把其父目录配置为 `customSkillDirs`。

## 最终回复格式

向用户交付时必须说明：Skill 路径、从几条会话提炼、使用了哪些成功证据、评测任务数、baseline/treatment 结果、安全扫描结论、仍未验证的边界，以及是否已经安装。不要用“已学会”替代这些证据。
